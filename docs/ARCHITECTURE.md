# Architecture

BookReader is one TypeScript + React codebase that ships two ways:

- **Desktop app** (macOS, Windows, Linux): a small native shell built with [Tauri](https://tauri.app/). The window uses the operating system's own web view, so the app is a few megabytes rather than a bundled browser. Users install it and open it from the Dock, Start menu or app launcher.
- **Web app / PWA**: the same UI served as static files. It runs in any modern browser and can be installed to the home screen on iPhone, iPad and Android, and it works offline.

PDF rendering is [pdf.js](https://mozilla.github.io/pdf.js/), export uses [pdf-lib](https://pdf-lib.js.org/), and
OCR uses [Tesseract.js](https://tesseract.projectnaptha.com/) (WebAssembly, offline). The UI is [React](https://react.dev/)
with [shadcn/ui](https://ui.shadcn.com/) components and [Tailwind CSS](https://tailwindcss.com/), built with [Vite](https://vite.dev/).

## Layers

```
┌──────────────────────────────────────── React UI (src/components, src/App.tsx) ──────────────────────────────┐
│ renders a ViewState snapshot · dispatches command ids · never mutates app state directly                      │
├──────────────────────────────────────── App layer (src/app) ─────────────────────────────────────────────────┤
│ AppController: tabs, preferences, tools, search sessions · commands.ts: every user action, by id · keymap    │
├──────────────────── Reader engine (src/engine) ─────────────────┬──────── Services (src/services) ───────────┤
│ ReaderPane · PageView · layouts · page turns · reflow ·          │ search · OCR · margin detection · PDF       │
│ annotation rendering & input  (plain DOM, for speed)            │ export · content id                          │
├──────────────────────────────── Models (src/models) ────────────┴─────────── Pure logic (src/lib) ───────────┤
│ Book · AnnotationStore · BookmarkStore · PdfDocument · types    │ history · geometry · reflow · crop maths ·   │
│                                                                 │ page slots · wheel gestures · deep links ·   │
│                                                                 │ export formats            (unit-tested)      │
├──────────────────────────────── Platform (src/platform) ─────────────────────────────────────────────────────┤
│ Platform interface → TauriPlatform (native dialogs, PDFs read from disk) | WebPlatform (IndexedDB, picker)   │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
        src-tauri/  — desktop shell (Rust): one window, file dialog and file-access plugins, nothing else
```

Dependencies only point downwards: `lib/` imports nothing app-specific; React components never reach into the
engine except through the `AppController` and its view state.

## Key ideas

**Commands, not callbacks.** Every action has an id (`view.zoomIn`, `nav.back`, `annotate.highlight` …)
registered once in `app/commands.ts`. The native menu, toolbar buttons, keyboard and selection bar all dispatch
ids, so an action behaves identically however it's triggered.

**One-way UI.** `AppController` rebuilds an immutable `ViewState` snapshot whenever something changes; React
reads it with `useSyncExternalStore` (`useAppState()`). Components that show model data (annotations,
bookmarks, search results) subscribe to that store with `useEmitter`.

**The engine is not React.** A 1,000-page book means thousands of canvases and layers whose lifetimes follow
scrolling, not component state. The engine builds them with plain DOM inside an element React hands over
(`Workspace` → `AppController.attachWorkspace`). React draws everything around and above it.

**PDF user space everywhere.** Annotation geometry, OCR words, search hits, history positions and deep links
are stored in PDF coordinates (points, origin bottom-left). Screen coordinates exist only at the edges
(`PageView.clientToPdf`, the SVG overlay transform), so zoom, crop and page splitting never invalidate data.

**Page slots.** What the reader shows is a list of _slots_ (`lib/page-slots.ts`): normally one per PDF page, but
a book scanned as open spreads can be split so each half is its own page. Two halves of a scan pair together
in two-page mode. Annotations still belong to the PDF page.

**Layered pages.** canvas → theme tint → transparent text layer → links → SVG annotations. Only the canvas
depends on zoom; the rest use CSS variables, percentages and a scale-1 `viewBox`.

**Page turns** (`engine/layouts/page-turn.ts`) animate a leaf hinged on the spine: its front is the page being
turned, its back the page that lands opposite, like a physical book. Neighbouring spreads are pre-rendered so
the back of the leaf is never blank. Trackpad input in page mode goes through `lib/wheel-gesture.ts`: when
zoomed in, two-finger scrolling only pans.

**Platform boundary.** Everything host-specific — reading files, storage, dialogs, menus — is behind the
`Platform` interface (`src/platform/platform.ts`). Nothing else checks whether it runs in the desktop app or a browser.

## Storage schema

Per book, keyed by `bookId` = SHA-256 of the file's bytes (so notes survive renames and moves):

- Desktop: `<userData>/library/<bookId>.json` (+ `<bookId>.ocr.json`, `<bookId>.crop.json`, `covers/<bookId>.jpg`)
- Web: IndexedDB database `bookreader`, keys `record:<id>`, `file:<id>` (a copy of the PDF), `extra:ocr:<id>`, …

## Adding a feature

1. Put pure logic in `src/lib/` and add a test in `tests/unit/`.
2. Add a command in `src/app/commands.ts`.
3. Trigger it from the UI (`useCommand()`) or the keymap.
4. If the UI needs new state, add it to `ViewState` in `app-controller.ts`.
5. Anything that touches files or storage goes through `Platform`, implemented for both the desktop shell and the web.
